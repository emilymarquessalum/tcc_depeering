


This was a folder created to implement what would essentially be testing, 
not only serving as validator but also to create "boundaries". 

## The idea of Boundaries

If you looked at data from IXPs and realized, as an illustrative example, that "often the average AS Path is between 2 and 4"... you could perhaps find it useful to know when that wasnt the case for the IXP you are analyzing. So I thought, TDD could not only work to help us write better and safer code that can change easily, but also help us identify "anomalies" in new data in comparison to what we already know, and bring us faster to new analysis. 

## Why is it not implemented then?

Unfortunetely, I concluded the timeframe I had available for development would make it hard to give time to this. Perhaps I was wrong, since it's argued that TDD saves time on the long run. However, that was the decision I took at the time.
